## 2025-03-01 - Type Confusion DoS in Express Route
**Vulnerability:** A Type Confusion vulnerability causing Denial of Service (DoS) was found in `src/server/llmRoutes.ts`. Unvalidated JSON payload containing `model` as an object (e.g. `{ model: { crash: true } }`) caused an unhandled `TypeError: modelId.toLowerCase is not a function`, leading to an Unhandled Promise Rejection which crashes the entire Node process (Node 22+).
**Learning:** In Express backend routes, relying purely on implicit typings of JSON request bodies can be fatal. If an attacker sends an Object where a String is expected and string-specific methods (`toLowerCase()`, `replace()`, etc.) are called without strict validation, it causes catastrophic exceptions. The `TypeError` exception within async endpoints bubbles up as unhandled promise rejections if the enclosing async logic doesn't explicitly `try-catch` all underlying synchronous sub-function calls properly, thereby destroying the process instance.
**Prevention:** Always enforce strict input type validation or explicitly cast JSON payloads before processing. Applying explicit typecasting (`String(val)`) immediately protects string-specific operations. Never blindly call methods on raw destructured values from `req.body` or `req.query` without verifying their JavaScript type at runtime, regardless of Typescript definitions.
